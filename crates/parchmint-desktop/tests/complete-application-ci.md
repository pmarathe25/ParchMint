# Complete-application CI seams

The normal complete-application suite builds the real production graph and
checks the exact 2,048-word and 250,000-word one/two-view fixture catalog on
every CI operating system. Existing crate and headless integration suites own
revision, session, ticket, save, recovery, History, search, spellcheck, and
export contract evidence.

The ignored tests in `complete_application.rs` are evidence boundaries, not
passing placeholders. Run them only with the named capability:

- A desktop interaction driver is required for canonical user-flow input and
  window observations.
- Real Windows, macOS, and Linux jobs are required for project interchange and
  native desktop behavior.
- Real native windows and clipboard access are required for high-DPI and
  clipboard evidence.
- Approved rendered Light/Dark references require a rendered multiwindow
  driver and product-owner visual review.
- Agreed reference hardware is required for latency and memory evidence.

`ProductionControls` and the test-support complete-application collectors
provide one-shot faults, operation observations, elapsed durations, and
optional resident-memory samples. They do not assign performance tolerances or
convert headless timings into release evidence. A future runner should record
its operating system and hardware profile, preserve the raw samples, and apply
only tolerances subsequently approved in the product specification.
